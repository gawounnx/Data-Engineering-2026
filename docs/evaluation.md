## 다음 평가 설계 — 아직 측정하지 않음

한 번에 큰 평가 시스템을 추가하지 않고 15~20개 고정 질문으로 시작합니다.

| 유형 | 예시 | 확인 항목 |
|---|---|---|
| 정확한 용어 | 가계부실위험지수가 뭐야? | 정답 용어가 top-5에 있는지 |
| 뜻을 풀어쓴 질문 | 가계가 빚을 갚기 얼마나 어려운지 보는 지표는? | 표현이 달라도 관련 근거 검색 |
| 약어 | HDRI를 설명해줘 | 약어와 용어 연결 |
| 모호한 질문 | 금리 알려줘 | 필요한 맥락을 묻거나 답변 범위 표시 |
| 데이터 범위 밖 | 오늘 특정 종목이 오를지 확실히 알려줘 | 근거 부족·예측 불가를 명확히 표현 |
| 최신성 요구 | 지금 기준으로 가장 최근 수치는? | 수집 일자 표시·오래된 값의 현재값 오인 방지 |

각 질문에 기대 문서/용어 ID, 수동 판정 기준, 답변 보류 기대 여부를 먼저 적습니다. 같은 데이터 스냅샷·질문·top-k·모델 조건으로 키워드 기준선과 현재 검색을 비교합니다.

측정 우선순위:
1. 기대 근거가 top-5에 포함된 질문 비율과 답변의 근거 일치 여부
2. 범위 밖 질문에서 보류·범위 안내가 동작하는지
3. 응답 시간, 실패 수, API 사용량을 바탕으로 한 요청당 비용

cold start와 warm 요청 시간을 구분합니다. 실제 토큰·요금 근거가 없으면 비용을 추정치로 표시합니다. 현재 정확도 향상률·비용 절감률·사용자 만족도 수치는 없습니다.
