# 개인 기여, 출처와 다음 작업

## 프로젝트 배경

FinFlow는 BDAI 데이터 엔지니어링 부트캠프에서 배운 수집·검증·적재·임베딩·검색·자동화·배포 흐름을 금융 서비스에 적용하며 시작했습니다. 강의의 일반 파이프라인 자체를 모두 독자 설계했다고 표현하지 않습니다.

강의자료 출처: https://drive.google.com/drive/folders/17LM7qv4AaPPku3VTNy_BEX08fn_YkpN4

폴더 목록에서 de-bootcamp-week1.zip, week2.zip, week3.zip, week4.zip, week5.zip, data.zip을 확인했습니다. 1~5주차 ZIP의 계획서·가이드와 3주차 평가 코드·DAG를 확인했습니다. data.zip 내부와 모든 소스의 줄 단위 비교는 수행하지 않았습니다. 강의 코드와 동일한 코드의 줄 단위 기여를 확정하지 않습니다. 강의 원본은 통째로 재업로드하지 않습니다.

## 기여 범위

| 구분 | 정리 내용 | 근거·추가 확인 |
|---|---|---|
| 학습 기반 | API→GCS→BigQuery, 청킹·임베딩, ChromaDB·Airflow·RAG·배포 학습 | 강의자료 및 기존 주차별 기록 |
| 금융 도메인 적용 | 금융위원회 시세 수집·검증·적재, 한국은행 용어 수집 | 현재 공개 코드와 개발 기록 |
| 데이터 확장 | 초기 69건에서 PDF 파싱·정제 770건으로 확장 | 후속 로컬 코드와 실행 결과 |
| 검색·서비스 확장 | 문장 청킹 개선, 용어 검색·근거 표시·Gemini·Streamlit, 주가 조회 | 앱 소스 반영(`finflow/`). 주가 조회는 앱 미연결 |
| 뉴스 확장 | 네이버 뉴스 수집·검증·중복 적재 방지·GCS·BigQuery·DAG·뉴스 벡터 검색 | 소스 반영(`finflow/scripts/`, `finflow/dags/`). 125행/재실행 0건 및 DAG 성공은 과거 기록 |
| 데이터 준비·안전성 | 컬렉션 존재 여부 검증, 인증 실패 처리, 스냅샷 압축 해제 보안 | `finflow/tests/` 자동 테스트 (2026-11-26 기준 185개 통과) |
| 배포 경험 | Cloud Build, Cloud Run 앱·Job, Secret Manager | 2026-11-26 배포 기록. 태그 URL 검증 후 트래픽 전환, 운영 앱 실제 질문 1건 확인 |

저장소 작성자와 개발 기록은 차가원입니다. 팀원 분담이나 독립 작성 비율을 증명할 자료는 확인하지 못했으므로 팀 성과·개인 단독 기여율을 만들어 쓰지 않습니다. AI 도구 도움 여부와 강의 기반 코드는 실제 작업 내역에 맞게 설명합니다.

## 면접에서 설명할 수 있는 이야기

- 문제: 금융 입문자가 뉴스의 낯선 용어와 숫자를 이해하기 위해 여러 출처를 오가는 불편
- 선택: 금융용어는 의미 검색, 정형 수치는 SQL 조회로 다루고 빠른 검증을 위해 Streamlit 사용
- 작업: 금융 도메인 수집·정제, 검색·응답 구성, 뉴스 파이프라인과 배포 확장
- 검증: 금융용어 770행, 뉴스 동일 입력 재적재 신규 0건, DAG 성공, 앱 배포 기록
- 한계: 사용자 수요 검증·검색 정량 평가·현재 배포 E2E·최신 코드 재현성 보완 필요

“정확도 향상”, “운영 비용 절감”, “실사용자 문제 해결 효과”는 실제 측정 전 성과로 기재하지 않습니다.

## 이후 고도화

기업 기본정보·재무정보, OpenDART 공시, ECOS, 주가 조회의 앱 연결, 사용자 로그 분석은 필요성과 기존 구현을 확인한 뒤 선택합니다. 뉴스 벡터 검색은 이미 구현돼 있습니다(`finflow/src/news_retriever.py`). 새 프레임워크나 별도 API 서버를 포트폴리오용으로 추가하지 않습니다.

사용자 가치 검증은 짧은 관찰 세션부터 시작합니다. “용어 뜻과 기사 맥락을 이해했는가”, “출처를 확인할 수 있었는가”를 기록하고 사용자 수·효과를 실제 측정한 범위로만 설명합니다.

## 공개 코드에서 확인한 구체적 확장

주가 수집기는 강의의 요청·메타데이터·JSON 저장 구조를 유지하면서 금융위원회 응답의 response 중첩과 resultType 파라미터에 맞췄습니다. DATA_GO_KR_KEY 환경변수, limit를 적용한 페이지 수집, HTTP 성공 이후 API resultCode 검사 등이 코드에 있습니다. 수집 직후 검증 호출은 현재 주석 처리되어 있어 완료 개선으로 포함하지 않습니다.
