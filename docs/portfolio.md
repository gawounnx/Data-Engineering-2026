# FinFlow 프로젝트 사례

## 한 문장 소개

금융 입문자가 낯선 용어를 출처와 함께 이해하도록, 금융 데이터 수집·정제와 의미 검색·설명 서비스를 연결해 발전시키는 개인 프로젝트입니다.

## 1. 발견한 문제

용어 사전만으로는 뉴스 맥락을 이해하기 어렵고, 기사만으로는 기초 개념이 부족할 수 있습니다. “용어 검색 → 개념 이해 → 기사 재독” 사이의 이동을 줄이는 것을 문제 가설로 설정했습니다. 인터뷰·사용성 관찰을 통한 수요 검증은 아직 수행 결과가 없습니다.

핵심 사용자: 대학생·사회초년생 등 금융 입문자.
핵심 시나리오: “가계부실위험지수가 뭐야?” → 관련 정의 검색 → 쉬운 설명 → 출처 확인.

## 2. 선택한 해결 방향

| 판단 | 선택 이유 | 대안과 한계 |
|---|---|---|
| 용어는 의미 검색, 수치는 SQL 조회 | 뜻이 비슷한 질문과 정확한 수치 조회의 요구가 다름 | 규모가 작으면 SQLite·키워드 검색이 더 단순함 |
| 원본을 GCS에 보관 | 수집 시점과 원문을 따라가 재처리하기 위함 | 보관만으로 적재 중복이나 원자성이 보장되지는 않음 |
| Streamlit으로 시연 | 질문·근거·답변 경험을 빠르게 확인하기 위함 | 최신 소스 반영·사용성 검증 필요 |
| 고정 질문으로 평가 시작 | 실패 유형을 재현하고 작은 변경을 비교하기 위함 | 아직 실행 결과가 없는 평가 계획 |

## 3. 직접 확장한 부분과 근거

부트캠프에서 배운 일반 파이프라인을 바탕으로 금융 도메인에 맞는 API 응답 처리·검증·적재를 적용했습니다. 현재 저장소에서는 다음을 코드로 확인할 수 있습니다.

- [주가 수집](../de-bootcamp-week1/scripts/day1_stock_crawler.py): 금융위원회 중첩 응답 처리, 인증키 환경변수, 페이지 수집, HTTP 이후 API 오류 검사.
- [시세 검증](../de-bootcamp-week1/scripts/data_quality.py): 필수 필드·건수·숫자 변환 가능 여부 확인.
- [클라우드 적재](../de-bootcamp-week1/scripts/day2_upload_stock_to_gcp.py): 업로드 전 검증, GCS 원본, BigQuery 시세와 적재 이력.
- [금융용어 검색](../de-bootcamp-week1/scripts/fin_terms_query.py): 입력된 벡터 JSON과 질문의 코사인 유사도 비교.

청킹·임베딩 기반 코드는 페르소나 실습과 함께 남아 있습니다. 모든 코드를 독자 설계했다고 표현하지 않으며 줄 단위 독립 기여율을 산정하지 않습니다. 후속 PDF 파서·RAG 앱·뉴스 파이프라인은 코드 반영 후 기여 근거를 보완합니다.

## 4. 관찰된 결과와 해석

기존 [평가 문서](evaluation.md)에는 금융용어 770행, 뉴스 동일 입력 재실행 신규 0건, DAG 테스트 성공과 배포 이력이 정리돼 있습니다. 이는 당시 환경의 데이터 처리·실행 기록이며 이번 정리에서 재실행하지 않았습니다.

현재 코드에서 주가 수집 직후 검증은 비활성이고, 주가 업로더는 append 적재입니다. 뉴스의 중복 처리 기록을 주가 파이프라인 전체의 멱등성으로 확대하지 않습니다. 청킹 변경 후 ETF 검색 성공 기록도 고정 평가 세트의 개선율로 표현하지 않습니다.

## 5. 남은 한계와 다음 실험

| 우선순위 | 작업 | 완료를 판단할 근거 |
|---|---|---|
| 1 | 최신 소스·의존성·설정 예제 반영 | 새 환경에서 질문 → 근거 → 답변 재현 |
| 2 | 기대 문서 ID를 포함한 고정 질문 작성 | 정상·모호·범위 밖·최신성 질문의 수동 기준 확정 |
| 3 | 기준선과 개선안 비교 | 같은 스냅샷·모델·top-k에서 검색과 답변 평가 결과 |

사용자 관찰에서는 출처를 확인할 수 있는지, 용어를 자기 말로 설명할 수 있는지 확인합니다. 관찰을 진행하기 전에는 사용자 효과를 주장하지 않습니다.

## 면접 설명 초안

“금융 뉴스를 이해할 때 용어와 기사 사이를 반복해서 이동하는 불편을 문제로 잡았습니다. 부트캠프에서 배운 데이터 파이프라인을 금융 API에 적용하고, 원본 보관과 SQL 조회, 의미 검색의 역할을 나눴습니다. 공개 코드에는 초기 수집·검증·적재·검색이 있고, 후속 앱과 뉴스 확장 기록은 최신 소스 반영이 필요합니다. 다음 목표는 새 환경에서 핵심 질문 흐름을 재현하고, 고정 질문으로 근거 검색과 답변 일치를 측정하는 것입니다.”

현재 설명 가능한 범위에 맞춘 초안이며, 실제 수행·검증이 추가되면 갱신합니다.
